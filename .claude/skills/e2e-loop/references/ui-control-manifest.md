# ui-control-manifest.md — generated UI-control coverage baseline

This is the runner's structural answer to a quiet coverage hole: every stable,
user-adjustable UI control has one state instead of relying on manual grep archaeology.
Run `bash scripts/ui-control-manifest.sh` after adding a control or a harness drive;
use `bash scripts/ui-control-manifest.sh --check` to prove the committed block is current.

## Inclusion and states

The generated block includes a literal `data-testid`, or the stable prefix of a dynamic
family, found in `apps/ui/src` whose local JSX window has an interactive element, role, or
event handler. It intentionally excludes static display-only ids and opaque computed ids
without a stable source key. Exact ids are matched as whole ids; only an explicitly declared
prefix may cover a family. This prevents `inventory-filter-trim` from falsely covering the
separate max-price control.

- **interacted** — a case action or uiDriver method drives the control.
- **read-only-checked** — a DOM assertion / settle check observes it, but no drive does.
- **never-touched** — no current case or driver reference reaches it.

The table below is generated. Keep runner guidance above or below the marker block; never
hand-edit its rows.
